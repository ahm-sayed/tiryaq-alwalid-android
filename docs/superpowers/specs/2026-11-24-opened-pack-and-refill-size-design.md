# تصميم ميزة الدواء المفتوح وسعة التجديد الكاملة (ترياق الوالد)

## الهدف والسبب
تطبيق **ترياق الوالد** يحسب استهلاك الأدوية تلقائياً بمرور الأيام لتنبيه المستخدم قبل نفاد الدواء. حالياً يعتمد التطبيق على `initialPills` لكلٍ من رصيد بداية الدورة وكمية التجديد الافتراضية، كما أن حقول `شريط` في `v1.0.10` منفصلة عن الحساب التلقائي والتجديد. النتيجة أن إضافة دواء **مفتوح بالفعل** أو **تصحيح الرصيد** أو **ترحيل المتبقي عند التجديد** يجعل التطبيق ينسى السعة الكاملة للشريط/العبوة.

## الأهداف
- حفظ **سعة الشريط/العبوة الكاملة (`packSize`)** بشكل دائم لكل دواء (جميع الأنواع، وليس `شريط` فقط) لاستخدامها تلقائياً عند التجديد.
- إضافة خيار **"الدواء مفتوح حالياً؟"** عند إضافة الدواء لإدخال الكمية المتبقية فعلياً الآن وبدء الحساب التلقائي منها دون تغيير السعة الكاملة.
- تحديث نافذة **تجديد الدواء** لتقترح `packSize` تلقائياً مع أزرار مضاعفة سريعة (`×1` / `×2` / `×3`) وإمكانية التعديل اليدوي، مع الإبقاء على خيار إضافة المتبقي السابق ومعاينة الرصيد بعد التجديد، دون تعديل `packSize`.
- إبقاء **تصحيح الرصيد** معدّلاً لرصيد الدورة الحالية فقط مع الحفاظ على `packSize`.
- التوافق الكامل مع البيانات المخزنة سابقاً في `localStorage` (`tiryaq_elderly_medicines_v4`) وإزالة ازدواجية حقول الشريط غير الفعالة في `v1.0.10`.
- رفع التعديلات بعد التحقق والاختبار إلى `ahm-sayed/tiryaq-alwalid-android` ليقوم GitHub Actions ببناء إصدار APK الجديد (`v1.0.11`).

## خارج النطاق وما يجب تجنبه
- **خارج النطاق:** نظام التعبئة المركّب (عدد الشرائط في العلبة × أقراص الشريط معاً في نفس النموذج)، أو تعديل محرك منبهات أندرويد الأصلي (`android-native`).
- **ما يجب تجنبه:** فقدان أو تشويه الأدوية المحفوظة حالياً على هاتف المستخدم، أو الإبقاء على حقول مكررة غير مؤثرة في الحساب، أو إضافة خطوات إضافية عند إدخال دواء جديد مغلق.

## القيود
- الحفاظ على مفتاح التخزين `tiryaq_elderly_medicines_v4` وقراءة الحقول القديمة (`stripCapacity` و`stripPillsRemainingAtStart` و`actualStripPills`) بسلاسة.
- واجهة عربية RTL متناسقة مع تصميم Tailwind الحالي وإمكانية الوصول.
- اجتياز `npm run lint` (`tsc --noEmit`)، واختبارات الوحدة `node --test`، و`npm run build` حتى ينجح مسار `.github/workflows/android-release.yml`.

## الأساليب المدروسة
1. **إضافة حقل دائم `packSize` مع الإبقاء على `initialPills` لرصيد بداية الدورة الحالية (تم اختياره):**
   - يفصل تماماً بين السعة القياسية والرصيد الفعلي للدورة، ويقرأ البيانات القديمة بدون أخطاء عبر دالة مساعدة (`packSize` ← `stripCapacity` للنوع `شريط` ← `initialPills`).
   - الميزة: بسيط، آمن مع البيانات الحالية، وأقل سطح تعديل.
2. **تحويل `initialPills` ليكون السعة الكاملة وإضافة `cycleStartPills` (مرفوض):**
   - يتعارض مع السجلات القديمة التي تغيّرت فيها قيمة `initialPills` بعد التجديد أو التصحيح، ويسبب التباساً في التسمية.
3. **نموذج علبة + شرائط (مرفوض في اختيار المستخدم):**
   - يزيد تعقيد نموذج الإضافة دون حاجة عند وجود مضاعفات سريعة (`×1` / `×2` / `×3`) في نافذة التجديد.

## قرارات المستخدم
- اختيار **الخيار الأول**: سعة كاملة موحدة لكل أنواع الأدوية + أوبشن "الدواء مفتوح حالياً" + تجديد يعتمد على السعة الكاملة المحفوظة.
- رفع التحديث مباشرة إلى GitHub (`ahm-sayed/tiryaq-alwalid-android`) بعد الانتهاء والاختبار لبناء `v1.0.11`.

## تفاصيل مقترحة للتنفيذ (قرارات المنفّذ للمراجعة)
- **القيمة الافتراضية عند إضافة دواء جديد:** عند اختيار النوع `شريط` تكون السعة الافتراضية `10` (ما لم يكتب المستخدم رقماً يدوياً)، و`30` لباقي الأنواع.
- **مؤشر التقدم وكارت الدواء:** يُحسب شريط التقدم نسبةً إلى `Math.max(initialPills, packSize)` حتى يظهر الشريط المفتوح بنسبة واقعية (مثلاً 4 من 10 = 40%) دون أن يتجاوز 100% عند ترحيل متبقي، مع إظهار سعة التجديد المحفوظة على الكارت بوضوح.
- **وضع التعديل (Edit):** يعرض السعة الكاملة (`packSize`) ويمكّن تعديلها أو تعديل رصيد بداية الدورة بدون تصفير العدّاد الجاري إلا عند تغيير الرصيد أو تاريخ البدء فعلياً.
- **التجديد السريع (`QuickRefillModal`):** يفتح على `1 × packSize` مع أزرار `×1` / `×2` / `×3` وحقل قابل للتعديل اليدوي ومعاينة فورية للرصيد بعد التجديد (شاملاً المتبقي المرحّل إن فُعّل).
